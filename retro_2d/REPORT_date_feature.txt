REPORT - PALSAR-2 mosaic date layer as a feature, 2025 k4r
=========================================================

Status: complete, 2026-11-02. User request: add the mosaic date layer as a feature; does it identify
sites; mirror one 2025 PALSAR + S2 + S1 classification and compare accuracies.
Mirror: 2025 k4r, 20 bands, n_iter 200, seed 42 (outputs\2025\k4r\, the standard result).
New run: same + palsar_date (21 bands), outputs\2025\k4r_date\.


ANSWER
------

1. Sites: the date identifies SITE GROUPS, not single sites.
   - 3 dates carry label cells; 16 of 18 sites are on one date only.
   - Cramer's V site x date 0.935; NMI 0.52; site from date 0.35 (prior 0.27).
   - 07-30 = 100 % Yawuru (10 sites). 08-27 + 12-03 = 89-97 % Dampier. V source x date 0.79.
   - "no canopy" is 21 % of 07-30 labels, 0.0 % of 08-27, 0.7 % of 12-03.
2. K-fold gain is small and positive.
   - Own searches: kappa 0.5950 -> 0.5986 (+0.004), OA +0.001, balanced +0.005.
   - Same base params, 3 fold seeds: kappa +0.005 to +0.008, all 3 positive.
   - palsar_date importance rank 4 of 21 (gain 0.086).
   - Date alone (majority class per date): kappa 0.13.
3. The K-fold gain is an upper bound. Stratified pixel K-fold puts neighbours of the same site in
   train and test. A site-group feature then adds site memory. Group CV is not used (user rule).
4. Maps: 89 % agreement (null 0.22, lift 0.67), mainland and pindan.
   - Seam steps get LARGER: 07-30 | 08-27 0.19 -> 0.26 class; 08-27 | 12-03 0.16 -> 0.21 class.
   - Strip class mixes move towards the class mix of their own label sites (07-30: C4 2.6 -> 0.8 %).
5. Recommendation: do not use the date as a feature.
   - The gain (+0.004-0.008 kappa) is near the noise and partly site memory.
   - It makes the strip artefact worse, not better.
   - In 2019-2024, 30-40 % of the mainland is on strips with no label cells: their date values are
     never seen in training, so the trees put them into an arbitrary neighbour date.
   - This supports PLAN_palsar_seamnorm.md (normalise strips at the seams), still waiting for approval.

METHOD
------

Date       JAXA <tile>_25_date_F02DAR.tif (21 tiles), nearest at the 2025 stack pixel centres
           (date_feature.py prep) -> outputs\palsar_date\date_2025_owngrid.tif, float32 days since
           2014-05-24, nodata -9999 (JAXA 0/1). 97.6 % of the grid has a date; all label cells do.
Feature    classify_retro.py --date (divergence 11): palsar_date as band 21, numeric.
Run        classify_retro.py --years 2025 --labels k4r --date --n-iter 200 --n-jobs 8 (2371 s),
           log classify_retro_k4r_date.log.
Analysis   date_feature.py analyse (log date_feature_analyse.log): label rows identical to base
           (asserted); noise floor = base best params, with / without date, fold seeds 42 / 7 / 123;
           map null = 8 x 8 px block shuffle, 5 draws.


CAVEATS
-------

1. 2025 only. In 2025 every large strip has label cells; 2019-2024 would be worse (ANSWER 5).
2. One search per feature set; the fixed-param seeds remove search noise but not model seed noise.
3. Seam steps have no placebo (only 2025 maps compared); they are base vs +date on the same pixels.
4. PALSAR calibration caveat (REPORT_palsar_date.txt caveat 7) applies unchanged.
